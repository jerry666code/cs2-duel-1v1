# Duel 1v1 Core

Metamod:Source-плагин для CS2: гибкое ядро дуэлей 1 на 1, активирующихся в конце раунда.
Построен на тех же интерфейсах, что и остальные плагины этого сервера (`cs2-menus`,
`cs2-vip`, `cs2-admin_system`) — использует `IUtilsApi` и `IMenusApi` из `cs2-menus-1.8.7`
как обязательные зависимости и не дублирует их функциональность.

## Зависимости

Загружаются через `addons/metamod/metamod.vdf`, **до** `duel`:

1. `cs2-menus` (core) — обязателен, отдаёт `IUtilsApi` (утилиты) и `IMenusApi` (кнопки/меню).
2. `IPlayersApi` (тоже из core) — обязателен, телепорт/оружие/steamid игроков.
3. `ICookiesApi` — опционален. Если не найден, плагин продолжает работать, но настройки
   автопринятия не переживают реконнект/смену карты (см. «Известные ограничения»).

Если `IUtilsApi`/`IMenusApi`/`IPlayersApi` не найдены при старте, плагин сам себя выгружает
(`meta unload`) и пишет причину в лог — как это делает `cs2-vip`.

## Структура модулей

| Файл | Ответственность |
|---|---|
| `duel.h` / `duel.cpp` | Бутстрап Metamod-плагина, получение интерфейсов, регистрация команд/событий, реализация `IDuelApi` |
| `duel_types.h` | Все структуры/enum'ы данных (оружие, арена, пресет, вызов, сессия дуэли) |
| `duel_config.h` / `.cpp` | Загрузка и валидация `weapons.cfg` / `arenas.cfg` / `presets.cfg` / `autoaccept.cfg` |
| `duel_manager.h` / `.cpp` | Вся игровая логика: state machine вызовов, таймеры, телепорт, урон, автопринятие, логирование |
| `duel_menu.h` / `.cpp` | Весь UI — построен **исключительно** на кнопках `IMenusApi` |
| `include/duel_api.h` | Публичный API (`IDuelApi`) для интеграции с другими плагинами |

Логика (`duel_manager`) не знает, как рисуются кнопки — она вызывает функции `DuelMenu::Show*`.
UI (`duel_menu`) не хранит состояние — он читает/пишет его через `DuelManager`. Конфиги
(`duel_config`) — отдельный слой, ничего не знает ни о меню, ни о логике дуэлей.

## Как устроен цикл дуэли

1. Игрок открывает меню (`!duel`, `mm_duel`, кнопка из другого плагина через `Duel_OpenMenu`)
   и жмёт **«Вызвать на дуэль»** → выбирает соперника → оружие → арену (или «Случайное»/
   «Случайная»). Каждый шаг — отдельная кнопочная менюшка (`ShowTargetMenu` → `ShowWeaponMenu`
   → `ShowArenaMenu`), состояние вызова хранится в `PendingChallenge`.
2. После выбора арены вызов отправляется цели. Если у цели включено автопринятие
   (`DuelAutoAcceptMode`) — дуэль подтверждается сразу. Иначе цель получает кнопки
   **«Принять» / «Отклонить»**.
3. Подтверждённый вызов попадает в очередь (`m_ConfirmedQueue`) и **не запускается сразу** —
   он ждёт события `round_end`.
4. На `round_end` все подтверждённые вызовы запускаются: сохраняется исходная позиция/здоровье/
   броня обоих игроков, они телепортируются на точки арены, с них снимается оружие, запускается
   отсчёт подготовки (`prep_time`).
5. По истечении подготовки выдаётся оружие/броня/каска по пресету, начинается сама дуэль
   (`duel_time`, опциональная регенерация здоровья).
6. Дуэль завершается по убийству (`player_death`), тайм-ауту, дисконнекту одного из участников,
   ручной отмене или смерти во время подготовки. Позиции/здоровье/броня восстанавливаются
   (если в пресете `restore_position 1`), результат пишется в лог.
7. **Страховка**: на событие `round_prestart` (начало следующего раунда) любая ещё активная
   дуэль принудительно завершается (`ForcedByRound`), чтобы дуэль не наложилась на новый раунд.

### ⚠️ Важно про тайминг раунда

Дуэль стартует на `round_end` и обязана уложиться в промежуток до `round_prestart`
следующего раунда — то есть в `mp_round_restart_delay` (и время фриза, если используется).
Настройте пресеты (`prep_time + duel_time`) так, чтобы они укладывались в это окно, **и/или**
увеличьте `mp_round_restart_delay` на сервере. Плагин не трогает этот cvar сам — это
осознанное решение, чтобы не вмешиваться в общий флоу раунда без ведома администратора.

## Кнопки (обязательный UI)

Все интерактивные элементы построены на `Menu`/`Items` из `IMenusApi` (`AddItemMenu`,
`SetCallback`, `DisplayPlayerMenu`), с поддержкой состояний `ITEM_DEFAULT` / `ITEM_DISABLED` /
`ITEM_HIDE`:

- **Вызов на дуэль** — `ShowMainMenu` → `ShowTargetMenu`
- **Принять/отклонить** — `ShowChallengeResponseMenu`
- **Выбор оружия** — `ShowWeaponMenu` (включая кнопку «Случайное оружие»)
- **Выбор арены** — `ShowArenaMenu` (включая кнопку «Случайная арена»)
- **Настройка автопринятия** — `ShowSettingsMenu` → `ShowHealthThresholdMenu` / `ShowWhitelistMenu`
- **Отмена вызова/дуэли** — `ShowCancelConfirmMenu`

Активный пункт текущего режима автопринятия и статус игрока («вы в дуэли», «ожидание ответа»)
показываются как заблокированные (`ITEM_DISABLED`) пункты меню.

## Конфигурация

Все конфиги лежат в `addons/configs/duel/` в формате KeyValues (как и у остальных плагинов
проекта) и перезагружаются командой `duel_reload` без рестарта сервера.

- **`weapons.cfg`** — список оружия: `classname`, отображаемое имя, категория
  (`melee`/`ranged`/`special`), `damage_mult`, `firerate_mult`, `range`, `banned`,
  `extra_items` (доп. предметы, выдаваемые вместе с оружием).
- **`arenas.cfg`** — точки телепорта для игрока A/B на каждой арене (`pos`/`ang`).
- **`presets.cfg`** — время подготовки, длительность дуэли, здоровье, броня/каска,
  регенерация, «случайное оружие для всех», фиксированная арена, восстановление позиции,
  `pre_commands`/`post_commands` (произвольные серверные команды при старте/завершении —
  точка расширения для баффов/погоды/освещения).
- **`autoaccept.cfg`** — режим и порог здоровья по умолчанию для игроков, ещё не менявших
  свои настройки.

### Что реально применяется в бою, а что — метаданные

- **`damage_mult`** реально влияет на бой: применяется через хук `HookOnTakeDamagePre` к
  урону, который наносит один дуэлянт другому во время активной фазы.
- **`firerate_mult`** и **`range`** — метаданные оружия (видны в меню, доступны другим
  плагинам через конфиг/README). Плагин намеренно не патчит тики атаки штатного оружия CS2 —
  это сильно рискованная низкоуровневая правка предсказания на клиенте, которая точно
  выходит за рамки этой задачи. Если нужна реальная скорострельность/дальность —
  это отдельная точка расширения через `IDuelApi`/`pre_commands`.
- Во время активной дуэли весь урон **не от назначенного соперника блокируется** — сторонний
  игрок не может вмешаться в чужую дуэль.

## Автопринятие

Режимы (`DuelAutoAcceptMode`): `Manual` (по умолчанию, кнопки «Принять/Отклонить»),
`Always`, `WhitelistOnly` (только от игроков из белого списка по SteamID64),
`HealthThreshold` (только если здоровье игрока ≥ порога), `Never` (вызовы автоматически
отклоняются). Всё настраивается через меню «Автопринятие» и доступно через `IDuelApi`.

## Логирование

Каждая дуэль (участники, оружие, арена, пресет, победитель, причина завершения, время)
пишется в `addons/logs/duel/duels.log` через `IUtilsApi::LogToFile`.

## Публичный API для других плагинов (`include/duel_api.h`)

```cpp
int ret;
IDuelApi* g_pDuel = (IDuelApi*)g_SMAPI->MetaFactory(DUEL_INTERFACE, &ret, NULL);
if (ret != META_IFACE_FAILED)
{
    g_pDuel->Duel_OnDuelEnd([](int iSlotA, int iSlotB, int iWinner, DuelEndReason eReason) {
        // например, начислить очки/деньги победителю
    });

    g_pDuel->Duel_SendChallenge(iChallengerSlot, iTargetSlot); // оружие/арена случайные
    bool bInDuel = g_pDuel->Duel_IsInDuel(iSlot);
    int iOpponent = g_pDuel->Duel_GetOpponent(iSlot);
}
```

Доступны запросы состояния, управление вызовами/дуэлями, управление автопринятием,
открытие меню (`Duel_OpenMenu`/`Duel_OpenSettingsMenu`) и подписка на события
(`Duel_OnChallengeSent`, `Duel_OnChallengeConfirmed`, `Duel_OnDuelStart`, `Duel_OnDuelEnd`).
Полные сигнатуры — в `include/duel_api.h`, там же комментарии по каждому методу.

## Команды

| Чат | Консоль | Действие |
|---|---|---|
| `!duel` | `mm_duel` | Открыть главное меню дуэлей |
| `!duelsettings` | `mm_duelsettings` | Открыть настройки автопринятия |
| `!duelcancel` | `mm_duelcancel` | Отменить текущий вызов/дуэль |
| `!duelaccept` | `mm_duelaccept` | Принять входящий вызов |
| `!dueldecline` | `mm_dueldecline` | Отклонить входящий вызов |
| — | `duel_reload` | Перезагрузить все конфиги дуэлей |

## Обработка краевых случаев

- **Дисконнект во время вызова/дуэли** — вызов отменяется с уведомлением второй стороны;
  активная дуэль засчитывается оставшемуся игроку победой (`Disconnect`), позиции
  восстанавливаются.
- **Смерть во время подготовки** — дуэль отменяется без победителя (`AbortedDuringPrep`),
  обе позиции восстанавливаются.
- **Отмена дуэли** — доступна на любом этапе до фактического боя через кнопку/команду;
  во время активного боя `Duel_ForceEnd`/`!duelcancel` завершает дуэль без победителя.
- **Начало нового раунда во время дуэли** — принудительное завершение (`ForcedByRound`),
  см. раздел про тайминг выше.
- **Выгрузка плагина** (`meta unload duel`) — все активные дуэли корректно завершаются,
  таймер тика снимается, хуки очищаются.

## Известные ограничения / точки расширения

- Настройки автопринятия хранятся в памяти на слот игрока и **не персистентны** между
  реконнектом/сменой карты в этой версии (cookies-провайдер опционален и на данный момент
  не подключён к автопринятию). При необходимости — добавляется через `ICookiesApi`,
  интерфейс для этого уже пробрасывается в `duel.cpp` (`g_pCookies`).
- `firerate_mult`/`range` в `weapons.cfg` — метаданные, не патчат тики атаки оружия (см. выше).
- `pre_commands`/`post_commands` в пресетах — общий, не привязанный к конкретной погоде/
  баффам механизм: администратор сам решает, какие серверные команды выполнять при
  старте/завершении дуэли.

## Сборка

Структура идентична `cs2-vip-main`: AMBuild + Metamod:Source + hl2sdk-cs2, собирается тем же
тулчейном/командой, с `-n duel -a duel`. HL2SDK сам по себе не входит в репозиторий — только
манифесты (`hl2sdk-manifests/`, скопированы из `cs2-vip-main`), AMBuild подтягивает реальный
SDK при сборке.

`AMBuilder` (как и у `cs2-vip-main`) ожидает соседнюю директорию `../SchemaEntity` рядом с
`cs2-duel-1v1`. В этом рабочем каталоге она называется `SchemaEntity-main` — переименуйте её
в `SchemaEntity` (или сделайте symlink) на уровне `CS2 Server/`, иначе сборка не найдёт
`schemasystem.cpp`/`module.cpp`/`ctimer.cpp`. Это уже требуется для сборки `cs2-vip-main` в
текущем виде, я не менял это соглашение.
